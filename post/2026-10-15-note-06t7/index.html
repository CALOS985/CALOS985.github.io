RSS订阅入门：用Inoreader搭建自己的AI资讯列表

把常看的科技网站订阅一次，以后打开一个页面，就能集中查看它们的新文章，不用每天挨个访问。RSS 最方便的地方就在这里：更新集中收取，内容自己挑选，读到哪里有记录，没时间细看的文章还能留着以后看。

这篇就用我的 OPML 订阅清单来演示。整理后的配置保留了 10 个 AI 与科技订阅源，导入 Inoreader 后，就能把这些分散的资讯放到同一个阅读列表里。

Inoreader 的免费计划可以订阅 150 个 RSS 源。像我这样自己看科技资讯、追踪常读的网站，完全够用了。这里的额度按订阅源计算，不是只能读 150 篇文章。官方计划页面，2026年10月14日核对。

01｜什么是RSS，为什么值得用

RSS 是一种发布网站更新的格式。网站把文章标题、链接、摘要等整理成一个可订阅的文件，阅读器定期读取它，你就能在一个界面查看多个网站的新内容。RSS 2.0 规范将它定义为网页内容聚合分发格式。

你可以把它理解为给网站更新准备的收件箱。关注谁，由你自己选；什么时候集中看，也由你安排。

这里有三个容易混淆的名字：

  • RSS 订阅源（Feed）：一个网站的更新地址，比如 GitHub 博客的 RSS 地址。
  • Inoreader：用来添加订阅、收取更新和阅读文章的工具。
  • OPML 文件：一份订阅地址清单。导入它，就不必逐个复制地址；它本身不保存所有文章正文。

对经常追踪科技资讯的人，最直接的好处是少跑几个网站。官网公告、技术博客和行业文章可以集中浏览，读过的内容能与未读内容区分，需要细看的文章也有地方暂存。

另一个好处是信息来源更容易控制。你可以长期追踪几个有用的作者，发现内容不合适再取消订阅，而不必每次从推荐流里重新找人。

RSS 能收到什么，取决于订阅源提供什么。有些源给全文，有些只给摘要；遇到摘要，打开原文继续读即可。

02｜这份订阅配置里有什么

我的这份 OPML 清单整理后共有 10 个订阅源，覆盖 AI 公司动态、行业文章、技术博客和开源资讯。下面就按这份配置说明，导入时不用逐个复制网址。

为了方便日后查找，我建议分成下面四组。原配置没有文件夹层级，这些分类可以在导入后自己建立。

  • 公司博客：OpenAI News、Claude Blog、Anthropic Engineering。
  • 社交动态：OpenAI(@OpenAI)、Anthropic(@AnthropicAI)。
  • 行业阅读：Latent.Space、The Rundown AI、Agili 的 Hacker Podcast。
  • 开发与开源：The GitHub Blog、逛逛GitHub。

内容来自某家公司的官网，不代表 RSS 地址也由这家公司提供。 这份配置中的部分公司博客使用第三方转换地址，X 动态和公众号内容也经过转换服务。第三方服务停止更新时，阅读器里的对应订阅也可能停下来。

刚开始用 RSS，不必急着搜集几百个源。先读这份清单中的几个，看看哪些内容确实能帮助自己的工作，再做增减。

03｜把订阅导入Inoreader

准备一个 Inoreader 账户，以及保存在电脑里的 .opml 文件。打开 Inoreader 官网并登录。下面按英文界面说明，方便对照按钮。

第1/3步：找到导入入口

点击最左侧带加号的 Add feed。展开的菜单中，Website 用于添加单个网站，Import feeds 用于导入订阅清单。

图 1｜从 Add feed 进入单个订阅添加或批量导入

如果手里只有一个 RSS 地址，就留在 Website 页面，把地址填进顶部的搜索框。例如：

https://github.blog/feed/

搜索后核对订阅名称和网址，再选择关注。有 OPML 文件时，直接进入 Import feeds 即可。这个入口也与 Inoreader 官方导入说明一致。

第2/3步：选择本地OPML文件

在 Import feeds 页面点击 Device，从电脑中选择 subscriptions.opml，或本教程配套的 示例订阅.opml，按页面提示完成导入。也可以把文件拖进虚线框。

图 2｜通过 Device 选择本地 OPML 订阅清单

这张图展示的是选文件的入口，还不是导入成功的结果。导入后要继续核对订阅列表，不能只看到上传入口就结束。

第3/3步：核对数量和状态

返回 Feeds，点击订阅列表顶部的齿轮，进入 Content 下的 Feeds 管理页。

这份 OPML 包含 10 个订阅源。空账户导入后，可按上面的清单核对名称；如果账户原本还有其他订阅，总数会更多。下图展示的是已有 11 个订阅的管理界面，用来说明检查位置，不是这份 10 源配置导入后的数量。

图 3｜核对订阅数量、启用状态和更新健康状态

这里值得看四列：Enabled 表示是否启用；Update 显示更新间隔信息；Last post 显示最近文章信息；Health 用颜色标记订阅健康状态。

图中的 Claude Blog 显示红色状态，Last post 为 N/A。它说明“订阅出现在列表里”和“已经正常收到文章”是两回事，后面会讲检查方法。

04｜分类、阅读和稍后再看

给订阅建文件夹

在左侧订阅名称上点击鼠标右键，选择 Add to folder。没有合适的文件夹时，再点 Assign to new folder，按提示输入名称，例如“开发与开源”。已有文件夹时，选择对应分类即可。

图 4｜通过 Add to folder 为订阅选择或新建分类

这一步可以从 The GitHub Blog 开始，再把同类订阅放到一起。以后只想看开发资讯，直接进入这个文件夹，不用在全部文章中逐条找。

用未读列表处理当天更新

点击左侧 Newsfeed，可以集中查看订阅收到的文章。顶部的 Unread 是未读筛选，All articles 则包含已读文章。

图 5｜在 Newsfeed 集中浏览文章并切换未读筛选

先扫标题和摘要，感兴趣的再打开。如果今天只想看某一个网站，点击左侧订阅名称就能缩小阅读范围。

卡片下方的书签形按钮是 Read later，可以把暂时没空细看的文章留待后续阅读，再从左侧 Saved 查看。顶部的 Mark all as read 会批量改变当前范围内文章的已读状态，别把它当成刷新按钮。

我的建议是固定一个短时间段查看更新，只留下确实想读的几篇。未读数字只是阅读状态，不必为了清零把每一条都看完。

05｜没有更新时，先检查哪里

如果某个源长时间没有内容，先到 Content → Feeds 查看对应行；也可以用管理页右上方的 With issues 筛选异常订阅。

先确认 Enabled 已开启，再查看 Last post 和 Health。像上面的 Claude Blog，当前已经显示红色健康状态，应该检查订阅地址，而不是反复导入整份 OPML。

接着打开原网站，看看最近是否真的发布过文章。如果原网站更新了，订阅仍异常，就核对 RSS 地址是否变化；使用第三方转换地址的，还要检查对应转换服务是否正常。

没有红色异常、只是晚了一会儿收到，也不一定有故障。管理页里不同源的 Update 值不同，订阅更新并非全部实时到达。

此外，文件夹菜单中的 Create rule、Filter feed 标有 Pro 提示。初次使用先完成订阅和阅读即可，自动化筛选可以等确实有需求时再研究。

如果你需要持续关注几家公司、技术作者或开源动态，这套方法很适合日常使用。先导入清单，检查状态，再挑一篇读完；一周之后，保留那些自己真正愿意打开的订阅。
